# 01. 機能仕様書 — TaskTimer

このドキュメントが**仕様の正典**。実装で迷ったらここに戻る。
ここに書かれていないことを勝手に作らない。書かれていることを勝手に削らない。

---

## 1. コンセプト

標準タイマーアプリの代替ではなく、**タスク時間計測ツール**である。

- タイマーは「料理を計るもの」ではなく「自分が何にどれだけ時間を使ったかを記録するもの」
- ログは「反省文」ではなく「実験データ」。自分という被験者を観察するための計測器
- **時間は途切れない**。あるタスクの終了時刻＝次のタスクの開始時刻。空白は作らない

### 中心にあるアイデア

タスク開始時に「**ゴール**」と「**予定時間**」を宣言させる。
予定時間が来たら逃げられない画面を出し、「延長するか、終えるか」を必ず選ばせる。
延長を繰り返すたびに「**このタスクに通算何分使うことになるか**」が突きつけられる。

## 2. 用語

| 用語 | 意味 |
|---|---|
| **セッション** | 1 回のタスク計測。開始〜終了までの 1 レコード |
| **ゴール** | そのセッションで達成したいこと（自由文） |
| **予定時間** | 見積もり（分）。これを超えると超過画面が出る |
| **超過** | 経過時間が予定時間を超えた状態 |
| **延長** | 超過画面で予定時間を追加すること |
| **合計所要時間** | 開始からの経過時間 ＋ これから選ぶ延長分。「計何分やることになるか」 |
| **切り替え** | 現在のセッションを終了し、同時に次のセッションを開始する 1 アクション。「中断」も「別のことを始める」なので、これと同じ操作で行う |
| **評価** | ◯（良い）/ △（普通）/ ✕（悪い）の 3 択 |

## 3. データモデル

### 3.1 `Session`（セッション＝タスク 1 回の記録）

| フィールド | 型 | 説明 |
|---|---|---|
| `id` | Long (PK, autoGenerate) | |
| `name` | String | タスク名 |
| `tag` | String | タグ（3.4 参照） |
| `goal` | String | ゴール。空文字可 |
| `plannedMinutes` | Int | 当初の予定時間（分）。延長で変わらない**初回の見積もり** |
| `totalPlannedMinutes` | Int | 予定時間 ＋ 全延長の合計（分）。延長のたびに増える |
| `startedAt` | Long (epoch millis) | 開始時刻 |
| `endedAt` | Long? | 終了時刻。進行中は null |
| `status` | Enum | `RUNNING` / `DONE` |
| `rating` | Enum? | `GOOD` / `NORMAL` / `BAD`。進行中は null |
| `ratingNote` | String? | 評価の理由 |

**不変条件**
- `status = RUNNING` のセッションは、DB 全体で**最大 1 件**
- `endedAt` が非 null なら `status = DONE`、`rating` も非 null
- `endedAt > startedAt`

### 3.2 `Extension`（延長の履歴）

| フィールド | 型 | 説明 |
|---|---|---|
| `id` | Long (PK) | |
| `sessionId` | Long (FK → Session) | |
| `minutes` | Int | 延長した分数 |
| `extendedAt` | Long | 延長を選んだ時刻 |
| `elapsedAtExtension` | Int | 延長を選んだ時点の経過分数（あとで振り返るため） |

延長を何回したかは、あとで「見積もりの精度」を分析するための重要なデータなので必ず個別に残す。

### 3.3 `TaskPreset`（タスク名のクイック選択用）

| フィールド | 型 | 説明 |
|---|---|---|
| `id` | Long (PK) | |
| `name` | String (unique) | タスク名 |
| `tag` | String | 前回このタスクで使ったタグ |
| `lastGoal` | String? | 前回のゴール（プレースホルダとして提示） |
| `lastPlannedMinutes` | Int | 前回の予定時間（初期値として提示） |
| `useCount` | Int | 使用回数 |
| `lastUsedAt` | Long | 最終使用時刻 |

**自動学習**：セッション開始のたびに、そのタスク名の Preset を upsert し `useCount++`。
ユーザーが手動で管理する画面は v1 では作らない（削除だけ設定画面から可能にする）。

**並び順**：`useCount DESC, lastUsedAt DESC`。同点なら最近使ったものが上。

### 3.4 `Tag`（タグ）

初期シードとして以下を投入する。既存の Notion システムと**必ず同じ名前・同じ色**にすること（v2 の同期で効いてくる）。

| 名前 | 色 |
|---|---|
| `Sleep` | 紫 |
| `Uni Study` | 黄 |
| `Job Hunting` | 赤 |
| `Hobby` | 青 |
| `Chore` | オレンジ |
| `For Myself` | 緑 |

v1 ではタグの追加・編集 UI は作らない（シード固定）。

### 3.5 `ExtensionPreset`（延長ボタンの選択肢）

| フィールド | 型 | 説明 |
|---|---|---|
| `id` | Long (PK) | |
| `minutes` | Int | 延長分数 |
| `useCount` | Int | 使用回数 |
| `isPinned` | Boolean | true なら常に先頭側に固定 |

**初期シード**：`5, 10, 15, 30`（分）
**並び順**：`isPinned DESC, useCount DESC, minutes ASC`
**編集**：設定画面で追加・削除・ピン留めができる

## 4. 画面仕様

画面イメージは `mockups/wireframe.html` をブラウザで開いて確認すること。

### 4.1 ホーム画面（進行中）

進行中セッションがある場合の表示。

```
┌────────────────────────────┐
│  [Job Hunting]             │  ← タグチップ（色付き）
│  ES執筆                     │  ← タスク名（大きく）
│                            │
│  🎯 A社のガクチカを書き切る    │  ← ゴール
│                            │
│       23:41                │  ← 経過時間（超巨大。等幅フォント）
│    予定 45分 / 残り 21分     │
│                            │
│  ████████████░░░░░░░░       │  ← 進捗バー
│                            │
│   [ タスクを切り替える ]      │  ← 主ボタン（これ 1 つだけ）
└────────────────────────────┘
```

- 経過時間は毎秒更新
- 超過後は経過時間が**警告色**になり、進捗バーは 100% を超えた分だけ別色で伸びる
- 表示は「経過時間」が主。「残り時間」は副。**何分やったかが本体だから**
- **「中断（記録して停止）」ボタンは置かない。** 記録が止まっている瞬間を作らないのがこのアプリの前提。
  「今のを終えて別のことを始める」は切り替えそのもの（2026-09-07 に Aki と確認して仕様を修正）
- 右上に設定画面（Notion 連携）への歯車アイコン

### 4.2 ホーム画面（未計測）

進行中セッションがない場合。**インストール直後の最初の 1 回だけ**表示される。
一度タスクを始めたら、以後この画面には戻らない。

```
┌────────────────────────────┐
│                            │
│      計測していません         │
│                            │
│   [ タスクを開始する ]        │
│                            │
│  ─ 最後の記録 ─              │
│  ES執筆 / 45分 / ◯          │
└────────────────────────────┘
```

### 4.3 タスク切り替えフロー

**「切り替える」を押してから次のタスクが走り出すまでのステップ。最短で 4 タップで終わること。**

進行中セッションがある場合は Step 1 から。ない場合は Step 2 から。

#### Step 1 — 前タスクの評価

```
┌────────────────────────────┐
│  ES執筆                     │
│  経過時間  1時間 12分         │  ← 必ず経過時間を見せてから評価させる
│  （予定 45分 / 160%）         │
│                            │
│  この時間の使い方は？          │
│   [ ✅ 良かった ]            │
│   [ 🫳 普通 ]               │  ← デフォルト
│   [ ❌ 悪かった ]            │
└────────────────────────────┘
```

- ✅ を選ぶ → 「何故時間の使い方が良かったのか議論しよう」で理由入力（必須）
- ❌ を選ぶ → 「何故時間の使い方が悪かったか議論しよう」で理由入力（必須）
- 🫳 を選ぶ → 理由入力なし。`ratingNote = "特に無し"` を自動セット

#### Step 2 — 次のタスク名

```
┌────────────────────────────┐
│  次は何をする？               │
│                            │
│  [ES執筆]  [講義]  [Sleep]   │  ← 頻度順プリセット。スクロールなしで
│  [筋トレ]  [移動]  [昼食]     │     6〜8 個が一目で見える密度
│  [Notion整理] [風呂]         │
│                            │
│  ＋ 新しいタスク…            │  ← タップでテキスト入力に切り替わる
└────────────────────────────┘
```

- **要件：スクロールせずに選べること。** チップは 1 行 2〜3 個、最大 4 行程度に収まる大きさ
- プリセットをタップすると、そのタスクの前回のタグ・ゴール・予定時間が Step 3/4 に**プリフィル**される
- 新規入力の場合はタグ選択ダイアログが挟まる

#### Step 3 — ゴール

```
┌────────────────────────────┐
│  ゴールは？                  │
│  ┌──────────────────────┐  │
│  │ A社のガクチカを書き切る  │  │  ← 前回のゴールを薄字でプレースホルダ表示
│  └──────────────────────┘  │
│         [ スキップ ]  [ 次へ ] │
└────────────────────────────┘
```

ゴールは空でも進める（スキップ可）。ただし空だと超過画面で見せるものがなくなるので、
プレースホルダで前回値を出して入力を促す。

#### Step 4 — 予定時間

```
┌────────────────────────────┐
│  何分でやる？                 │
│                            │
│  [15]  [25]  [30]  [45]     │  ← よく使う値。頻度順
│  [60]  [90]  [120]          │
│                            │
│  自由入力: [ ___ ] 分         │
│                            │
│         [ 開始する ]          │
└────────────────────────────┘
```

### 4.4 超過画面（OverdueActivity）— **このアプリの心臓部**

予定時間に到達した瞬間、**他のアプリの上に全画面で**出る。ロック画面の上にも出る。

```
┌────────────────────────────┐
│                            │
│      予定時間を超過           │
│                            │
│  🎯 A社のガクチカを書き切る    │  ← ゴールのみ再掲（タスク名は出さない）
│                            │
│   経過 47分 / 予定 45分       │
│        104%                │  ← 超過率。大きく
│                            │
│  ─────────────────────      │
│  あと何分やる？               │
│                            │
│  [+5]  [+10]  [+15]  [+30]  │  ← 選択式。タップで選択状態が変わるだけ
│                            │
│    合計所要時間              │
│      57分                  │  ← ★ ここだけが更新される。1 か所に集約
│  ─────────────────────      │
│                            │
│   [   延長する   ]           │  ← 延長分が選択されている時だけ活性
│   [ タスクを終える ]          │
└────────────────────────────┘
```

#### 超過画面の挙動（重要）

1. **延長ボタンは即実行しない。「選択」するだけ**
   - 各ボタンに合計時間を併記するのではなく、画面下部の「合計所要時間」1 か所が書き換わる
   - これにより「+30 を選んだら計 77 分か…さすがに長いな」という判断ができる

2. **合計所要時間の定義**
   ```
   合計所要時間 = 現在の経過分数 + 選択中の延長分数
   ```
   例：45 分予定で開始 → 47 分経過して超過画面 → `+10` を選択 → 「57 分」と表示

3. **「延長する」を押したら**
   - `Extension` レコードを追加
   - `Session.totalPlannedMinutes += 選んだ分数`
   - 新しい期限で `AlarmManager` を再セット
   - 画面を閉じてブロック解除。通知常駐は継続

4. **「タスクを終える」を押したら**
   - 4.3 の Step 1（評価）に遷移し、そのまま切り替えフローに入る
   - つまり「終える」＝「次のタスクを始める」。時間の空白を作らない

5. **超過率の表示**
   ```
   超過率 = 経過分数 / 当初の予定分数 × 100
   ```
   分母は `plannedMinutes`（当初の見積もり）であって `totalPlannedMinutes` ではない。
   **見積もりの精度を測るのが目的だから、延長で分母を膨らませては意味がない。**
   150% を超えたら数字を警告色にする。

6. **バイブのみ。音は鳴らさない**
   - 短めのパターンを 2〜3 回。例：`[0, 400, 200, 400, 200, 600]`
   - 画面が表示されたら停止

7. **逃げ道の封鎖**
   - 戻るボタン無効（`onBackPressed` を握りつぶす）
   - ホームボタンで抜けようとしたら、オーバーレイが画面を覆って引き戻す（5 章）
   - **非常口**：画面右上を 3 秒長押しで「強制的に閉じる」を出す。バグで端末が使えなくなる事故を防ぐため**必ず実装する**

### 4.5 履歴画面

- 日付ごとにグルーピングしたリスト（新しい順）
- 各行：時刻レンジ / タスク名 / タグチップ / 所要時間 / 評価アイコン / 延長回数
- 日付ヘッダに「その日の合計計測時間」と「タグ別の内訳バー」
- 行タップで詳細（ゴール、評価理由、延長の履歴）
- v1 では編集不可。**閲覧のみ**（記録の改ざんを防ぐ思想）

### 4.6 設定画面

- **Notion 連携**（6.3 参照。Phase 2.5 で実装済み）
  - 連携 ON/OFF、トークン（マスク表示・保存・削除）、データベース ID
  - 送信状況（未送信 N 件 / 失敗 N 件 / 最後のエラー）、「再試行」「今すぐ送信」
  - デバッグビルドのみ「日またぎのテスト記録を作る」
- 延長プリセットの追加・削除・ピン留め
- タスクプリセットの削除（使わなくなったものを消す）
- **権限の状態表示と再取得導線**（5 章参照）。ここが一番大事
- 強制力の ON/OFF トグル（オーバーレイブロックを使うか）
- データのエクスポート（JSON / CSV）

## 5. 通知・常駐・強制力の仕様

### 5.1 常駐通知（フォアグラウンドサービス）

セッションが `RUNNING` の間ずっと表示され続ける。

```
TaskTimer                              23:41
ES執筆 · Job Hunting
🎯 A社のガクチカを書き切る
予定 45分 / 残り 21分
[ 切り替え ]
```

- 経過時間は 1 秒ごとに更新（バッテリー影響が大きい場合は 5 秒間隔に落としてよい）
- スワイプで消せないようにする（`setOngoing(true)`）
- タップでホーム画面へ
- 「切り替え」アクションで切り替えフローを直接起動

### 5.2 期限の検知

**サービス内のカウンタで期限判定してはいけない。** Doze モードでサービスが止まると鳴らない。

- 期限は `AlarmManager.setExactAndAllowWhileIdle()` で登録する
- サービスのカウンタは**表示専用**
- 端末再起動時は `BOOT_COMPLETED` を受けて、DB の `RUNNING` セッションからアラームを再登録する

### 5.3 強制力の実装

超過時：

1. `AlarmManager` が `BroadcastReceiver` を叩く
2. バイブ開始
3. **full-screen intent 付きの通知**を出す → `OverdueActivity` が全画面で起動
4. 同時に **`BlockerOverlayService`** を起動し、`TYPE_APPLICATION_OVERLAY` の全画面ビューを被せる
5. `OverdueActivity` で「延長」か「終える」が選ばれたらオーバーレイを解除

オーバーレイを併用する理由：full-screen intent だけだと、ホームボタンを押されると裏に回ってしまい、そのまま他のアプリを使えてしまう。オーバーレイはホーム画面の上にも残るため、これが実質的なブロックになる。

**必ず守ること**
- オーバーレイのビューには「非常口」（右上長押し 3 秒）を実装する
- オーバーレイを起動する処理は `try/catch` で囲み、権限がなければオーバーレイなしで続行する（クラッシュさせない）
- 設定画面のトグルで完全に無効化できるようにする

## 6. 集計ロジック

### 6.1 日をまたぐセッションの扱い

既存の Notion システムでは GAS が 23:59 にレコードを物理分割していたが、**アプリ側では分割しない。**

- セッションは 1 レコードのまま保持する
- 日別集計は**クエリ時に日境界で按分**して計算する
  例：23:00〜翌 07:00 の Sleep → 当日に 59 分、翌日に 420 分を計上
- 理由：物理分割は不可逆でデータが汚れる。表示のたびに計算すればよい
- Notion に送るときだけ、既存スキーマに合わせて日境界（0:00）で分割して送る（6.3）

### 6.2 表示する集計

- 日別：合計計測時間、タグ別内訳
- タスク別：平均所要時間、平均超過率、延長回数の平均（**見積もり精度の可視化**）

### 6.3 Notion への自動記録（Phase 2.5。当初 v2 だったが 2026-09-07 に前倒し）

ローカルの Room DB が唯一の正で、Notion へは一方向に送るだけ。詳細は `docs/06_NOTION_INTEGRATION.md`。

| アプリでの操作 | Notion で起きること |
|---|---|
| タスクを開始する | 新しい行が「進行中」で増える（名前・time.start・タグ・ゴール・予定時間（分）） |
| 切り替える | 今の行が「完了」になる（time.end・評価・メモ）。続けて次の行が「進行中」で増える |
| 延長する | **何も送らない。** 行は「進行中」のまま |
| 延長後に終える | 終了時刻は延長も含めて実際に終えた時刻。「予定時間（分）」は当初の見積もりのまま |
| 日をまたいで終える | 0:00 で分けて複数行にする。先頭は既存行を書き換え、2 日目以降は「完了」で新規作成 |

- 連携を ON にした後に開始したセッションだけ送る。既存の記録は送らない
- オフラインなら端末に溜めて、ネット復帰後に順番どおり自動送信（アプリを開いていなくてもよい）
- トークン誤りなど直さないと通らない失敗は設定画面に残し、「再試行」で送り直す
- **Notion 側の失敗で計測が止まったりアプリが落ちたりしてはならない**
- トークンは設定画面で入力し、端末内で暗号化して保存する。ソースコードに書かない

## 7. v1 でやらないこと（明示的なスコープ外）

以下は実装しない。頼まれてもいないのに作らないこと。

- Notion からの取り込み（双方向同期）。送るだけ
- ホーム画面ウィジェット
- 常駐オーバーレイ（音楽アプリと同時表示）
- アクセシビリティサービス
- 複数タイマーの同時実行
- 音によるアラーム
- タグの追加・編集 UI
- 履歴の編集・削除
- クラウドバックアップ、アカウント、ログイン
- ダークモード以外のテーマ切り替え（**ダークモードのみで作る**）
